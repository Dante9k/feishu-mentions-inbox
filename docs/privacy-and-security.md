# 隐私与安全设计

## 数据分类

| 数据 | 是否保存 | 位置 | 默认生命周期 |
|---|---|---|---|
| 消息可读正文/摘要 | 是 | 主数据库、受限 Base | 180 天或撤回时立即清除 |
| 图片、文件、音频、视频本体 | 否 | 不下载 | 不适用 |
| 群名、发送人显示名、时间、消息 ID | 是 | 主数据库、受限 Base | 当前版本不自动删除元数据 |
| 用户 `user_id` / `open_id` | 是 | 主数据库、受限 Base | 用户生命周期及审计需要 |
| OAuth access/refresh token | 是 | 主数据库加密字段 | 停用时清除，过期时失效 |
| App Secret 和服务端回调密钥 | 否 | 环境或外部密钥管理 | 由部署方轮换 |
| 原始事件 payload | 临时 | 主数据库事件队列 | 成功后立即清空；失败事件最迟随正文保留期清除 |

正文保留期由 `CONTENT_RETENTION_DAYS` 控制。降低保留期前应确认业务与审计要求；提高保留期前应完成隐私影响评估。

## 访问模型

- 普通员工只通过 Base 受限角色访问自己的收件箱和设置行；
- 普通员工只能修改处理状态、处理备注和自己的 `@所有人` 开关；
- 管理员接口同时要求应用层 Bearer Token 和网关层公司内网/管理员身份；
- 飞书应用仅对管理员启用名单和已授权员工生效；
- Base 管理员在第一版技术上可以查看全部正文，这是明确接受而非被消除的风险。

行级隔离依赖飞书多维表格高级权限配置，无法由后端单元测试完全证明。每次角色、字段、自动化或应用数据范围变化后，都要重新执行三账号权限门禁。

## 主要威胁与缓解

| 威胁 | 缓解 |
|---|---|
| 伪造或重放飞书事件 | 签名、Verification Token、加密事件和 5 分钟时间窗口 |
| Base 自动化伪造回调 | 独立 Bearer Token、实体与 record 映射校验、字段白名单 |
| 跨用户状态修改 | `item_id` 与 Base record 映射校验，状态位于个人待办 |
| 重复/并发消息 | 数据库唯一约束和幂等事件键 |
| 外部群内容误采集 | 群属性查询失败即重试；外部、跨租户和不支持群拒绝处理 |
| 数据库泄露暴露 OAuth Token | Fernet 加密字段；加密根密钥与数据库分离保存 |
| 日志或公开 issue 泄露 | 日志不记录 payload/Token；Issue 模板强制脱敏提醒 |
| Base 暂时不可用导致丢消息 | 主数据库和 transactional outbox |
| 已撤回或过期正文继续暴露 | 撤回即时清正文，周期性执行保留策略并重新投影 |
| 管理 API 暴露公网 | Bearer Token + 网关访问控制；生产默认关闭 API 文档 |

## 部署方责任

上线前必须确认：

- [ ] 飞书应用权限和通讯录数据范围遵循最小必要原则；
- [ ] 外部群和无法确认属性的群不会进入采集；
- [ ] Base 普通员工角色通过三个真实账号完成查看、搜索、导出和编辑隔离验证；
- [ ] TLS、管理员身份、速率限制和请求体限制已配置；
- [ ] 所有密钥独立生成并存入受控密钥系统；
- [ ] 主数据库、备份和日志的访问已受控并满足所在地法规；
- [ ] 正文保留期限、管理员可见性和员工告知方式已获得组织批准；
- [ ] 已建立员工离职、应用停用、数据删除和安全事件响应流程。

## 密钥轮换

- `ADMIN_API_TOKEN` 和 `BITABLE_CALLBACK_TOKEN`：更新服务后同步更新调用方，短窗口内完成切换；
- `FEISHU_APP_SECRET`、Verification Token、Encrypt Key：在飞书后台轮换后立即更新服务并验证事件；
- `OAUTH_STATE_SECRET`：轮换会使未完成的 OAuth state 失效，已授权用户不受影响；
- `TOKEN_ENCRYPTION_SECRET`：不能直接替换；需要先解密并以新密钥重加密所有 Token，或要求全部用户重新授权。

任何疑似泄露都应视为安全事件：先撤销/轮换，再调查访问日志和影响范围，不要等待代码修复后才处理凭证。

## 公开项目脱敏

允许公开的内容：最小合成事件、随机 UUID、`example.com` 域名、`tenant-a`、`user-1` 等明显虚构值。

禁止公开：真实或可关联的消息正文、员工姓名、群名、群 ID、用户 ID、租户 ID、Base ID、生产 URL、日志、数据库、备份、OAuth code、OAuth Token、App Secret、事件解密密钥和回调 Bearer Token。

公开 GitHub 仓库前，按 [GitHub 发布前检查清单](github-release-checklist.md) 审计暂存文件与历史。`.gitignore` 只能阻止未跟踪文件的误提交，不能替代人工审查，也不能清除已经进入 Git 历史的敏感数据。
