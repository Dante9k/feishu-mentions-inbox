# 验收与分批上线清单

[返回 README](../README.md) · [部署指南](deployment.md) · [隐私与安全](privacy-and-security.md)

## 自动化测试

- [ ] 单元测试、静态检查和编译检查全部通过。
- [ ] 使用计划上线的 SQLite 或 PostgreSQL 模式启动容器，重启服务后事件和 outbox 不重复。
- [ ] 模拟多维表格 5xx/限流，数据库仍保留待办，恢复后自动补写。
- [ ] 重复、乱序和投影回调不会回滚状态或形成同步循环。
- [ ] 100–200 用户直接 @和大群 `@所有人` 突发压测，符合条件记录 60 秒内可见。

## 三账号门禁

- [ ] 同一条消息直接 @员工 A、B，生成两条独立待办。
- [ ] A 修改状态/备注，B 的状态和版本不变。
- [ ] 未启用、未授权、已停用员工不生成新待办。
- [ ] `@所有人` 只分发给群内已激活且主动开启的员工。
- [ ] A 无法查看、搜索、导出、修改 B 的任何记录。
- [ ] A 不能修改正文、成员、源 ID、版本等只读字段。
- [ ] 撤回消息正文被清除；未完成转忽略，已完成状态保留。
- [ ] OAuth 失效后显示“授权失效”，重新授权可恢复。
- [ ] 机器人进群、退群、群解散后覆盖状态正确更新。

## 分批上线

- [ ] 先固定 3 个测试账号，权限隔离全部通过。
- [ ] 选择 10–20 人、少量内部群试运行。
- [ ] 扩到约 50 人，观察 API 限流、outbox 重试和 Base 容量。
- [ ] 再扩到管理员完整名单；单个普通员工角色不超过 200 人。
- [ ] 每批上线前清零“待加机器人”，或由业务负责人书面确认无法覆盖群。

## 运维和故障演练

- [ ] 主数据库按公司标准加密备份，并完成一次恢复演练。
- [ ] App Secret、OAuth 加密密钥和两个 API token 存入密钥管理，不进入仓库或日志。
- [ ] 告警覆盖健康检查失败、事件/outbox 重试堆积、OAuth 失效和覆盖率下降。
- [ ] 验证 180 天正文清理；消息撤回立即清正文。
- [ ] 停用员工后不再产生待办，OAuth token 清除，Base 文档和角色权限移除。
- [ ] 记录管理员可查看全量正文的阶段性风险接受人和复审日期。
